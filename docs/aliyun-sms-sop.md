# EBM中转站阿里云短信服务 SOP

本文用于 EBM中转站（基于 New API）的中国大陆注册验证码短信开通、上线、巡检、故障处理和密钥轮换。它不保存任何 AccessKey 明文；所有密钥只能存放在受控的密码管理工具和 Coolify 环境变量中。

## 1. 适用范围与成功标准

适用场景：向中国大陆手机号发送注册验证码，模板变量名固定为 `code`。

只有同时满足以下条件，才可将短信注册视为正式可用：

1. 企业资质已审核通过，短信签名已关联正确的企业资质。
2. 签名通过阿里云平台审核，并完成移动、联通、电信三网的运营商实名制报备验证。
3. 验证码模板审核通过，模板变量为 `code`。
4. 专用 RAM 用户只拥有 `dysms:SendSms` 权限，AccessKey 状态正常。
5. Coolify 中五项环境变量齐全，重新部署后 `/api/status` 返回 `sms_verification_ready: true`。
6. 使用移动、联通、电信号码各完成至少一次真实收件测试，发送记录显示成功，短信签名、内容和验证码均正确。
7. 邮箱验证保持可用，作为短信故障时的注册兜底方式。

> `sms_verification_ready: true` 只表示应用环境变量齐全，不代表余额、签名报备、模板、RAM 权限或运营商通道一定正常。最终以上线前的真实收件测试为准。

当前运营商报备状态为移动、联通、电信均“已报备待验证”。实际发送记录出现：

```text
签名实名制报备问题。应运营商要求，各短信发送通道需完成对应签名的实名制报备。(386)
```

这不是“余额不足”的证据，而是当前签名尚未通过对应发送通道的实名制报备。正式开放短信注册前，必须完成第 7 节的三网真实收件验收；在此之前保留邮箱注册，并建议关闭短信验证开关。

## 3. 阿里云侧开通流程

### 3.1 开通短信服务并准备企业资质

1. 使用企业实名认证的阿里云账号开通短信服务。
2. 进入“国内消息 → 资质管理”。
3. 新增或选择企业资质，确认状态为“审核通过”。
4. 核对企业名称、统一社会信用代码、证件有效期、管理员和联系电话等信息。
5. 不使用个人资质承载企业商业短信。

产出物：一项状态为“审核通过”的企业资质。

### 3.2 申请签名并完成运营商实名制报备

1. 进入“国内消息 → 签名管理”。
2. 申请与企业资质一致、可明确识别主体的企业全称或简称签名。
3. 将签名关联到第 3.1 节已审核通过的企业资质。
4. 等待阿里云平台审核通过。
5. 在“运营商报备结果”中分别检查移动、联通、电信状态和失败原因。
6. 状态进入“已报备待验证”后，使用对应运营商的自有或团队测试号码进行少量真实发送测试。
7. 发送后同时核对“发送记录”和手机实际收件结果；不要只看签名的“可用-正常”。

阿里云官方提示，运营商实名报备平均需要 5–7 个工作日，部分情况需要 7–10 个工作日，且实际可能更长。新业务应至少提前 10 个工作日办理。报备未完成时不得承诺短信注册已上线。

产出物：三网报备验证和真实收件验收记录。

### 3.3 申请验证码模板

1. 进入“国内消息 → 模板管理 → 添加模板”。
2. 选择验证码类模板。
3. 模板变量使用 `${code}`，变量名必须与应用发送参数一致。
4. 文案应明确业务动作、有效期和安全提醒，避免营销内容、链接或联系方式。
5. 等待审核通过并记录模板 Code。

本项目当前模板内容：

```text
您正在进行账号注册，验证码为${code}，10分钟内有效。请勿向他人泄露，如非本人操作请忽略。
```

产出物：审核通过的模板 Code，例如 `SMS_511735352`。

## 4. RAM 最小权限与 AccessKey

### 4.1 创建专用程序用户

1. 在 RAM 控制台创建仅供 EBM中转站发送短信的程序用户。
2. 不开启不必要的控制台登录权限。
3. 不使用阿里云主账号 AccessKey。
4. 不与其他系统共用该 RAM 用户或 AccessKey。

当前用户：`ebm-sms-sender`。

### 4.2 创建并绑定最小权限策略

创建自定义策略 `EbmSmsSendOnly`，内容如下：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["dysms:SendSms"],
      "Resource": ["*"]
    }
  ]
}
```

将策略绑定到专用 RAM 用户。该用户无需 `AliyunDysmsFullAccess`、`AdministratorAccess` 或其他管理权限。

### 4.3 创建和保管 AccessKey

1. 为专用 RAM 用户创建 AccessKey。
2. 创建时立即存入受控的密码管理工具；AccessKey Secret 通常无法再次查看。
3. 不把 AccessKey 写入代码、Git、文档、截图、聊天、工单或构建日志。
4. 只在 Coolify 的服务端环境变量中配置密钥，并确保变量不会暴露到前端构建参数。

## 5. Coolify 配置与部署

在 EBM中转站应用的环境变量中配置：

```dotenv
ALIBABA_CLOUD_ACCESS_KEY_ID=<RAM用户的AccessKey ID>
ALIBABA_CLOUD_ACCESS_KEY_SECRET=<RAM用户的AccessKey Secret>
ALIYUN_SMS_REGION_ID=cn-hangzhou
ALIYUN_SMS_SIGN_NAME=苏州橡数数字科技
ALIYUN_SMS_TEMPLATE_CODE=SMS_511735352
```

操作要求：

1. 精确选择生产应用，避免把密钥写到其他应用、预览环境或前端环境。
2. 保存五项变量后执行重新部署；仅重启旧容器不一定会加载新配置。
3. 部署日志中不得打印 AccessKey。
4. 部署成功后检查：

```bash
curl -fsS https://ai.ebm001.com/api/status
```

返回结果至少应包含：

```json
{
  "system_name": "EBM中转站",
  "sms_verification_ready": true
}
```

如果 `sms_verification_ready` 为 `false`，先检查五项变量是否齐全和部署是否使用了最新环境变量，不要直接反复申请新密钥。

## 6. 应用开关

进入“系统设置 → 身份验证 → 基本身份验证”：

- 邮箱验证：保持开启，作为兜底方式。
- 短信验证：只有第 7 节全部通过后才开启。

应用行为：

- 邮箱和短信同时开启：注册页显示两种验证方式，用户可以选择。
- 只开启邮箱：短信故障或报备期间的推荐状态。
- 只开启短信：不推荐，短信供应商或运营商故障会直接阻断注册。

## 7. 上线验收

### 7.1 测试准备

准备移动、联通、电信的中国大陆手机号各一个，号码应由测试人员本人控制并同意接收测试短信。记录测试时间、运营商、脱敏手机号、发送结果、阿里云 Request ID 和实际收件结果。

### 7.2 逐网测试

对每个运营商依次执行：

1. 在注册页选择短信验证并输入测试手机号。
2. 获取验证码一次，等待页面返回结果。
3. 在阿里云“发送记录”中检查本次请求的状态和失败原因。
4. 确认手机在合理时间内收到短信。
5. 核对短信签名、文案、6 位验证码和 10 分钟有效期提示。
6. 使用收到的验证码完成一次测试注册；测试账号按内部规则清理。

不要连续点击发送。本项目限流为：

- 同一手机号：每分钟 1 条、每小时 5 条、每天 10 条。
- 同一 IP：每分钟 10 次请求。

### 7.3 上线门禁清单

- [ ] 企业资质审核通过且信息正确。
- [ ] 短信签名关联正确的企业资质。
- [ ] 移动真实发送和收件成功。
- [ ] 联通真实发送和收件成功。
- [ ] 电信真实发送和收件成功。
- [ ] 模板审核通过，变量名为 `code`。
- [ ] RAM 用户只绑定发送所需的最小权限。
- [ ] `/api/status` 中 `sms_verification_ready` 为 `true`。
- [ ] 阿里云发送记录无报备、签名、模板、权限或欠费错误。
- [ ] 邮箱验证可正常使用。
- [ ] 开启短信验证后，注册页显示短信入口并能完成注册。

任何一项未通过，均不得将短信注册标记为正式可用。

## 8. 日常巡检

每周或每次变更后检查：

1. 阿里云账号是否欠费，短信服务是否可用。
2. 签名状态和移动、联通、电信的运营商报备结果是否异常或失效。
3. 模板是否仍为审核通过状态。
4. 最近发送量、成功率、失败码和异常增长。
5. Coolify 最近一次部署是否健康，`/api/status` 是否正常。
6. 邮箱注册兜底是否仍可用。
7. RAM 用户是否出现额外策略、异常 AccessKey 或异常调用。

建议监控项：短信发送失败率、每分钟请求数、供应商错误码分布、注册验证码完成率和短信费用突增。

## 9. 故障处理

先保存发生时间、脱敏手机号、运营商、应用日志中的阿里云 `code`、`message`、`request_id`，再按下表处理。不要记录验证码或 AccessKey。

| 现象或错误 | 判断 | 处理 |
| --- | --- | --- |
| `386`，提示签名实名制报备问题 | 对应运营商通道报备未完成，不等同于余额不足 | 检查签名关联资质和三网报备详情；按对应运营商进行少量真实测试并等待报备；期间关闭短信验证、保留邮箱验证 |
| `sms_verification_ready: false` | 应用未读到完整配置 | 检查五项环境变量并重新部署 |
| 权限不足、鉴权失败 | AccessKey、RAM 策略、密钥状态或归属不正确 | 核对 AK 所属 RAM 用户、`EbmSmsSendOnly` 绑定情况和是否存在优先级更高的 `Deny` |
| 签名或模板错误 | 环境变量与审核通过的名称/Code 不一致 | 逐字核对签名名称、模板 Code 和变量名 `code`，重新部署 |
| `429` 或“短信发送过于频繁” | 命中应用限流 | 根据 `Retry-After` 等待；不得通过换 IP 或批量号码绕过限制 |
| 页面显示发送失败，但阿里云有记录 | 阿里云拒绝请求或通道失败 | 以发送记录和应用日志中的准确错误码处理，不凭经验猜测 |
| 页面显示发送失败，阿里云无记录 | 请求可能未到阿里云 | 检查应用开关、参数、Turnstile、限流、网络和后端日志 |
| 怀疑余额不足 | 尚未形成结论 | 查看阿里云费用/余额和发送记录的准确失败原因；只有证据明确指向欠费时才充值 |
| 个别运营商收不到 | 该运营商报备或通道异常 | 按运营商拆分发送记录和测试，不以另一个运营商成功代替验收 |

### 9.1 紧急降级

当短信连续失败、成功率明显下降或供应商状态不明时：

1. 在“系统设置 → 身份验证 → 基本身份验证”关闭短信验证。
2. 确认邮箱验证保持开启，并实际测试一次邮箱注册。
3. 在阿里云发送记录和应用日志中定位准确错误码。
4. 修复后重新执行第 7 节验收，再开启短信验证。

关闭短信验证开关即可完成业务降级，不必为一般通道故障立即删除环境变量或 AccessKey。若怀疑密钥泄露，应立即禁用泄露的 AccessKey，并按第 10 节轮换。

## 10. AccessKey 轮换

建议至少每 90 天检查一次密钥使用情况，并在人员变更、疑似泄露或异常调用时立即轮换。

1. 确认 RAM 用户仍只有最小权限。
2. 创建第二组 AccessKey，存入密码管理工具。
3. 在 Coolify 中同时更新 `ALIBABA_CLOUD_ACCESS_KEY_ID` 和 `ALIBABA_CLOUD_ACCESS_KEY_SECRET`。
4. 重新部署并确认 `/api/status`、发送记录和一次真实收件测试均正常。
5. 禁用旧 AccessKey，观察无异常后删除旧 AccessKey。
6. 记录轮换日期、操作者、验证结果和旧密钥删除状态；记录中不得包含密钥值。

任何时候都不要先删除唯一可用的旧 AccessKey，再测试新 AccessKey。

## 11. 变更与留痕

以下变更必须重新部署并执行第 7 节验收：

- 更换短信签名、模板或关联企业资质。
- 修改 RAM 用户、权限策略或 AccessKey。
- 修改五项 Coolify 环境变量。
- 修改短信 SDK、发送参数、验证码逻辑、限流或注册流程。

每次变更至少记录：日期、原因、变更项、审批人、执行人、测试号码运营商、阿里云 Request ID、验收结果、回滚结果和应用版本。手机号必须脱敏，AccessKey 和验证码禁止入档。
